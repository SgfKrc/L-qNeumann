## 一、三个硬约束

### 1.1 token 带宽：15–16 bit / 周期

一次前向只能送出 **15–16 bit**（一个 token 的 payload）。而一次前向能算 **119,808 个 MAC**。

**宽窄比约 7500:1。** 任何「输出宽」的优化都会被这个比例压死：

| 若 1 token 算完 64×64 matvec | 输出 64 个结果的成本 | 总 token | 对 CPU 的加速 |
|---|---|---:|---:|
| 每个结果 31-bit | 128 token | 129 | 40× |
| 每个结果 14-bit | 64 token | 65 | 80× |
| **结果不取回（链式）** | 0 | **1** | **5200×** |

**所以加速器的设计原则是「输出窄、状态宽、能反复用」**，不是「算得快」。

### 1.2 吞吐上限：1 记录 / token

一次前向只吐一个 token。这条锁死了单流吞吐——**想突破只能扩宽 token 总线，而 payload 位宽 =
log2(词表)**。要把一个 32 位值塞进 1 个 token，需要 **2³² 行 embedding**。这条路在物理上关死。

**batching 是唯一绕过它的方式**（多行并行），但 batch 只提高 head 的并行度，ffn 侧已经饱和。

### 1.3 访存：85% 的时间在 gather

```
chip 步 204.5 μs
├─ gather         85%
├─ reduce/argmax   9%
├─ atomic          1%
└─ matmul        0.07%
```

**每个乘加要配 4 次 4 字节随机读**（残差 X、残差 Y、int32 索引、fp32 权重）。fp32 FMA 峰值
6.9 T MAC/s，而随机 gather 饱和吞吐只有 167 G/s——**差 41 倍**。

**这是「慢」的真正原因，不是算力不够。**

## 二、被实测否定的优化方向

| 方向 | 实测 | 为什么 |
|---|---|---|
| **persistent kernel**（24 launch → 1） | **1.017×** | launch 间隙只占 1.5%；23 个栅栏 +53 μs，阶段 2 会慢 14% |
| **流水线**（IF/ID/EX/MEM/WB） | **负收益** | 分支率 26.5%，每支冲刷 2–3 周期，0.726 → 0.56 指令/token |
| **并行复制电路**（k 路发射） | **纯亏** | 层数 ×k、时钟也 ×k，收益抵消 |
| **新硬件设备**（MDU / AES / SHA / zlib） | 1.0–1.3× | 受 token 带宽限制；深度换不来宽度 |
| **gather 按字读**（bridge） | **负收益**（380→388） | gather 在 bridge 里总共只占 ~54 token |

## 三、被真实拿到的优化

| 方向 | 收益 | 依据 |
|---|---:|---|
| **chip token 连续 burst**（一次 `run(k)`） | **2.31×** | 去掉每 token 的 GPU→CPU 同步（200 μs 级别） |
| **head 拆 CTA + 跨 CTA 归并** | **1.307×** | head grid 31→248，每行 339→217 μs |
| **batch B=8/32** | 1.35–1.53× | head 并行度（ffn 拿不到） |
| **SB/SH 记录压缩** | sieve −18.8% | token 数下降，间接减少访存 |
| **calc 清零精确化** | `4+3` −61% | 7×64 条强制 bmac = 448 token |

**规律**：**收益都在「去掉同步」和「减少访存次数」，不在「加并发」和「加硬件」。**

## 四、一个诚实的判断

**它比真 CPU 慢 6–8 个数量级，这不是 bug，是架构代价。**

- 真 CPU 3 GHz，每周期 1 指令
- 这台机器 2,782 token/s（现在 4.06× 后约 11,000 token/s），每个 token 是一整次前向

**它的价值不在速度，在「不需要主机」**——它真的把一台计算机放进了权重里，而且真的在跑。

毕设如果只做「优化性能」，答辩会被问「那你证明了什么」。**更好的说法是**：
1. 我证明了这台机器可行（构造性）
2. 我找到了它的瓶颈（访存，不是算力）
3. 我给出了在瓶颈下接近最优的实现（4.06×）
