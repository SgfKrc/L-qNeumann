## 0. 结论

1. **现在的编码接近信息论最优**：族内浪费为 0，时间效率 88%（1.134 token/指令 vs 理论下限 1.0）。
2. **「token 流双关」（让 chip token 同时是可读文本）不做**——不是不可能，是**可读化要 6.2–10.3 倍 token**，不划算。
3. **「让族可读」是将来可做的方向**（见 §6）：族标签本身已是 2 bit 的可读语义，成本落在语言熵预算内。

## 1. 一个重要区分：「最坏情况」vs「实际流熵」

| 项 | 值 |
|---|---|
| payload 位宽（最坏情况） | 15–16 bit |
| **实际流熵 H1**（7 个程序实测） | **0.6–4.0 bit/token** |
| 实际触及的词表 | **1.03%**（4,079 / 394,164） |

**为什么这么低**：因为**程序在 ROM 里，ROM 在 snapshot 里**——执行是确定的，token 流只携带数据依赖的那一点点信息。

> **chip token 流的本质是「时钟 + 可观测行为」，不是数据总线。** 15–16 bit 载荷是对「最坏情况（未知数据）」保留的地址空间，99% 的时间用不到。

## 2. 现状编码：接近最优

`circuit/chipformer/rv/spec.py:72-85`：

| 族 | 大小 | payload 位 | 占词表 |
|---|---:|---:|---:|
| V / F0 / F1 / VC | 32,768 ×4 | 15 | 33.2% |
| J / R / VE / VH | 65,536 ×4 | 16 | 66.5% |
| BYTE / QD / BD | 512/128/256 | 9/7/8 | 0.22% |
| F2 / FLT / HEX / QS | 4/8/16/16 | 2/3/4/4 | 0.04% |
| 控制（NT…SC，8 个） | 8 | 0 | 0.002% |

`VOCAB = 394,164`，`log2 = 18.588 bit`。**所有族大小都是 2 的幂 → 族内浪费恰好为 0 bit。**

### 三个不同的「效率」

| 定义 | 数字 | 说明 |
|---|---:|---|
| **地址效率** payload/log2(V) | **80.7%** / 86.1% | 差额是**族标签**（自描述类型的代价） |
| **熵效率** H/流 | H0 5.0–8.9；**H1 0.6–4.0** | 程序在 ROM 里的必然结果 |
| **时间效率** 下限/tpi | **1.0/1.134 = 88%** | **这才是该当目标函数的** |

**为什么是 15 bit 而不是 16**：因为 `15+15+2 = 32`——两个 15-bit 载荷加 2-bit 的 F2 恰好覆盖 32 位值。这是刻意对齐的分解。

## 3. 双模态词表：已经实现（分区，不是重叠）

```
vocab_size = 642,496 = 248,320（Qwen 文本）+ 394,164（RV32 chip）+ 12
```

`merge.py:10-15` 写明每行承载**两份信息**：

> every Qwen vocabulary row carries the ballast and its text features in the chip dims (is_text, tau, its first 16 UTF-8 bytes, the `<tool_call>` flags, and **for the 260 printable tokens the output code of their echo**)

**所以**：
- 一行 = Qwen 语义（4608 维）+ chip 特征（ballast / is_text / tau / UTF-8 前 16 字节 / 260 个 printable 的 output code）
- Qwen 的 260 个可打印 token **同时**是 chip 的 Q 族输出码
- **这是「同一 id 两种解读」的正确形态：维度子空间 + 门控（mute）**

### 为什么不能「语义重叠」（省 2.13 GiB）

| 障碍 | 说明 |
|---|---|
| **embedding 冲突** | 一行 4608 维必须同时是「the」的语义几何和「V(5)」的 20-bit code；code 会泄漏进语言输出 |
| **自指模式信号** | 同 id 双义后，解码器要知道「现在读哪种」，而 token 流是唯一总线 |
| **收益错位** | 省内存（2.13 GiB），**不省带宽**——两个通道各有独立预算，共享行不共享 bit |

**结论**：分区是干净解；重叠只省内存，代价是语义冲突 + 自指模式。

## 4. 自定义编码：空间 3–8%

**p=16 是甜点**（`2×16 = 32`，任何 32 位值 2 token）：

| 程序 | tpi 现状(p=15) | p=16 | 变化 |
|---|---:|---:|---:|
| cover | 1.824 | 1.353 | **−25.8%** |
| fuzz1 | 1.485 | 1.265 | −14.8% |
| print | 1.176 | 1.059 | −10.0% |
| mem | 1.166 | 1.163 | −0.3% |
| **加权（11 程序）** | **1.134** | **~1.09** | **−3~5%** |

- 词表 525,236（+33.2%），embedding **+1.13 GiB** bf16
- 地址效率反而升到 **84.2%**（大族占比更高）
- **p=18 起收益归零**（32 位值已经 2 token）

**等价路径**：族标签算术编码（把 3.59 bit 的静态标签按 H(fam)≈2 bit 编码，回收 1.4–2.2 bit/token）——收益相同，实现比扩词表重。

**天花板**：tpi 1.134 → 1.0 是 12% 上限，**不是 payload 位宽**，是「一条指令 = 13 层组合逻辑 = 一个 token」的时序约束。

## 5. 信息论边界（定量）

同一个随机 32-bit 值，用不同编码送进 Qwen：

| 编码形式 | token/值 | bit/token | 相对 |
|---|---:|---:|---:|
| **chip（15-bit 族）** | 2.74 | **11.7** | 1.0× |
| raw 4 bytes（byte-level） | 4.00 | 8.0 | 1.5× |
| hex 文本 `0x%08x` | 8.79 | **3.64** | 3.2× |
| 十进制文本 | 9.73 | **3.29** | 3.6× |
| JSON `{"v":%d}` | 13.73 | **2.33** | 5.0× |
| 自然语言可理解句 | — | **1–3** | 4–12× |

**同一执行写成可读汇编清单**：

| 程序 | chip token | 汇编清单 token | **可读代价** |
|---|---:|---:|---:|
| cover | 31 | 193 | **6.2×** |
| mem | 457 | 4,434 | **9.7×** |
| loop | 625 | 6,447 | **10.3×** |

**对照**：本仓库自然语言（34,831 字 / 18,896 token）——unigram 8.35 bit/token（上界），bigram **3.31 bit/token**。

### 硬约束的形式化

> 每 token 携带 b bit ⇔ 观察者惊讶 b bit。b=15 时 p=3×10⁻⁵。
> **「可读」要求序列落在语言分布内 ⇒ 联合概率高 ⇒ 每 token 惊讶度低 ⇒ 每 token 信息 1–3 bit。**

**这不是词表问题**：词表只能改「容量上界」，不能改「可理解性 ↔ 信息量」的对偶。要传 11.7 bit/值的随机数据且可读，token 数至少 ×4（宽松）到 ×11.7（严格）；实测汇编形式 **6–10×**，与理论一致。

## 6. 将来计划：让「族」可读（性能优化的一部分）

**核心洞察**：

> **结构是可读的，数据不必。**
>
> hex/JSON 只有 2.3–3.6 bit/token，不是因为「文本低效」，而是因为格式 token 不承载数据、却占 token 位。
> 反过来：**「结构可读 + 数据透明」是最优折中**——格式 token 可预测（对 LLM 免费），数据 token 满熵（对 LLM 透明）。

**而 chip token 的「族」本身就是 2 bit 的可读语义**：`V`=值、`J`=跳转、`NT`=无写入、`BYTE`=输出。**这是免费搭在 token 里的意图标签**（H(fam) = 1.4–2.2 bit，**正好落在语言熵预算内**）。

### 要做什么

把 4-bit 族 id 暴露给 Qwen（构造 embedding，映射到 `add`/`jump`/`print` 一类语义），让 Qwen 知道「现在在跳转/在输出」，而精确值留在电路里。

| 项 | 值 |
|---|---|
| 带宽 | **2 bit/token**，落在语言熵预算内 |
| 代价 | 需要构造 embedding（映射族 → 词），**可能要训练** |
| 收益 | Qwen 能「理解」程序在做什么（不是数值，是意图） |
| 风险 | 可能需要微调，而微调要动 dense 部分（与「不动 Qwen」冲突） |

**归属**：这既是「语义增强」也是「性能优化」——因为它能减少 text token 的数量（模型不需要被 dump 出所有细节就能理解程序）。

**状态**：**待评估**。先做 A+B（两端裁剪，M4）、方向 1（按 token 选层）、C（稀疏存储），这三件是性能主线。

## 7. 替代方案（按性价比排序）

| # | 方案 | 收益 | 状态 |
|---|---|---|---|
| 1 | **保持分区双模态**（现状） | 已是最优形态 | ✅ 已实现 |
| 2 | **payload 15 → 16** | tpi −3~5%，地址效率 80.7 → 84.2% | 待评估 |
| 3 | 族标签算术编码 | 等价收益，实现更重 | 不做 |
| 4 | **族可读**（§6） | Qwen 理解意图，可能减 text token | 待评估 |
| 5 | 按需结构化文本（调试用） | 不占总线 | 不做 |
| 6 | 训练模型理解电路状态 | 要动 dense，与「不动 Qwen」冲突 | 不做 |

**一句话**：「让 token 流既有意义又高效」不成立，因为「有意义」的定义就是「LLM 能低惊讶度预测」，而那恰恰就是「每 token 信息少」。但项目已经找到了正确的解法：**语义放在族标签（2 bit，免费），数据放在 payload（15 bit，电路独占），可读性只给结论、不给数据。**
